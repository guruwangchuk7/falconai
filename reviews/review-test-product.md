## Issue 0 — Card-quality go/no-go gate (scope / sequencing)
Make AI-generated mediation-card quality an explicit gate, hardened per owner's terms:
- **Position:** end of Phase 1, not the start. Card quality is downstream of retrieval; gating
  before ingestion works tests a strawman → false negative.
- **Metric:** blind A/B with the actual Phase 0 disagreement participants (human vs AI card,
  unlabeled, "which would you rather have had in the moment"). NOT similarity to the hand-written
  ideal — that measures similarity-to-Guru. **Corrects how §12.7 is written today.**
- **Pre-registered bar:** name the threshold and N before running (e.g. "AI preferred-or-tied in
  ≥2/3 of blind comparisons"), with no stake in the outcome.
- **No-go branch:** fail → 2 weeks prompt/context iteration → re-gate once → second failure cuts
  mediation; Falcon ships as context + summary (still a product). A gate without this second
  sentence is a checkpoint in costume.
- **What passing buys:** necessary, not sufficient — timing/latency/mid-argument readership are
  Phase 4 unknowns. Pass = "keep building," not "thesis confirmed."
- **PRD edits:** §17 Phase 1, §12.7 metric, G3/G4.

## Test / Eval

### T1 — Golden set is under-powered (accepted)
10 Phase 0 meetings is a thin base for tuning many independent thresholds (salience, stance,
gap, premise-confidence, addressee). No plan to grow the labeled set before Phase 4 (production
thumbs-data only accrues post-launch). Grow the set deliberately; report precision/recall with
confidence intervals, not point estimates. Issue 0's blind-A/B correction lands here too.

### T2 — Catastrophe boundaries need continuous property tests, not a one-time red-team
F9.1a (ACL intersection) and F9.2a (blame-neutral) are single-failure-catastrophe boundaries.
- **Continuous invariant tests gate every build:** (a) no published citation resolves outside
  `session_visibility_scope`; (b) no shared card carries a performance judgment about a named
  person. **Keep the Phase 4 red-team as an added adversarial layer.**
- **PRD edits:** §12.7, F9.1a, F9.2a (name the invariants as build gates).

### T3 — Injection defense: structural parts move to Phase 1/2, suite stays Phase 4
- The attack-window argument is the **weakest** reason (Phase 1-2 needs an insider poisoning
  their own repo to steer a single-recipient private nudge; no shared card). Don't oversell it.
- **Real reasons:** (1) trust-tier **schema retrofit** is expensive later; (2) **eval baseline**
  — shipping the omission diff in Phase 2 gives Phase 4 ten weeks of benign-traffic fire-rate
  telemetry, so the gate is interpretable (a 3% fire rate means something); (3) **provenance-
  gating is structural** — building Phase 2 nudges without it means rewriting the output path
  later, same retrofit class as the column.
- **Separate schema from policy:** ship the trust-tier column + a coarse 3-tier default in
  Phase 1; expect tier assignments to be wrong until thousands of artifacts are seen. Schema is
  expensive to change; policy is a config edit.
- **Shadow mode in Phase 2:** run gating + omission diff in shadow (log what they'd block, block
  nothing) on private low-stakes nudges to build the baseline with zero over-blocking risk; flip
  to enforce when shared cards arrive in Phase 4.
- **PRD edits:** §17 (Phase 1/2 add structural defense), F7.2, §14 (trust-tier column).

## Performance

### P1 — Cost ceiling vs value (pool the budget + engagement signal + visible degrade)
- **"Burns budget" is a bad proxy for value** — high spend also = router over-firing on an
  agreeable review, a long-not-heated planning, or a deliberately-steered session (A3). Headroom
  keyed on spend amplifies the malfunction (see CX-2).
- **Value signal independent of spend = card engagement so far** (published + engaged → extend;
  published + dismissed → the classifier is wrong, more budget makes it worse).
- **Pool the budget = the real fix:** per-workspace-per-month ceiling; per-session cap only as a
  runaway backstop at a multiple of normal. A 5x-average meeting is trivially affordable in a
  pool funded by the many quiet meetings. Removes the conflict rather than adding an override.
- **Drop "operator-raisable"** (no human in a live-meeting loop). **Keep auto-degrade but make
  it legible** — raising the threshold drops the marginal (least valuable) card, which is correct
  triage; the failure is that it's *invisible*.
- **Measure before tuning:** if p99 session spend ≈ 2x p50 there's no problem; set the pool from
  Phase 1 telemetry (same discipline as the 10s SLO — derive, don't defend a guess).
- **PRD edits:** §12.6, §12.10.

### Performance folds (accepted)
- **Restate §12.1 as p95/p99** with per-stage timeout budgets (AD-3 already flags; the tail is
  on STT + the two LLM calls).
- **Context Packs as a cache-stable prefix** (pack = cached prefix, rolling transcript = uncached
  suffix) or ~40 agent wakes/meeting miss Anthropic prompt caching and the $0.60 agent COGS line
  (§12.2) balloons.

## Outside Voice — independent challenge (Claude subagent, fresh context)

Went where the systems review didn't: product, legal, economics, social mechanics. Reviewer
verdicts and owner decisions below.

### OV-1 / OV-14 — The shared card's disclosure of asymmetry IS the social harm — RESOLVED
F9.2a neutralizes performance judgments, but publicly surfacing "one side didn't know Y" marks
the uninformed party in front of peers regardless of phrasing — the exact harm the private nudge
exists to avoid. **Decision: add a Wizard-of-Oz live-card test in Phase 1/2, before the
Coordinator.** Design it so it can't lie:
- **Handicap the wizard to the system's real capability:** card text pre-generated by the actual
  model from the team's real artifacts, fixed template; the operator's only live choice is *when
  to send*. Isolates the social question from content quality (Issue 0's job).
- **Don't trust self-report** (politeness pressure is the very force under test). Measure
  behavior: did the argument change course? did the marked person's talk-time drop over the next
  5 min (withdrawal = face damage)? Ask individually + async a day later with the asymmetric
  question ("would you want this with your manager present / when you were the one who missed the
  PR?"). Best instrument: offer it for their next meeting — do they turn it on (revealed
  preference)?
- **Vary the power gradient** (most consequential sampling choice): peer-peer = mild; IC before
  manager = serious; junior before skip-level = severe. At least one session with a manager in
  the room; expect it to produce the real finding.
- **Test two card shapes:** asymmetric ("X didn't know Y") vs symmetric/face-saving ("you're
  reasoning from different versions of the API contract" — externalize the conflict onto a
  missing artifact, not judgment). If the symmetric shape lands and the asymmetric doesn't, it's
  a design finding, not a kill. This is CX-1/T2's constrain-the-schema principle applied to card
  rhetoric: make blame inexpressible.
- **Free hedge:** Phases 1–2 build solo nudges + context regardless, so nudge-only + Decision
  Record exists by ~month 3 — which is what makes the aggressive early test safe (a bad result
  redirects, doesn't strand). Don't concede the differentiator preemptively.
- **Practical:** piggyback Phase 0 teams, cards from their own earlier transcripts in a later
  meeting; get up-front consent that "Falcon may show cards during this meeting."
- **PRD edits:** §17 (Phase 1/2 WoZ test), §20 (behavioral + revealed-preference metrics),
  F9.2 (support a symmetric/face-saving card shape).

### OV-4 / OV-9 — System-audio fallback = non-consenting recording — RESOLVED: CUT from v1
Blocker-class (wiretapping exposure in all-party-consent states incl. CA). **Decision: cut
system-audio fallback (F4.7) from v1**, because the gating alternative doesn't actually work:
- You can't collect consent through a UI the unpaired person doesn't have — "affirmative ack"
  can only come from the installed user (a self-attested "I told them"), which is §12.4's
  offloading with a compliance artifact stapled on (same overclaim pattern as A3/F7.2).
- Per-jurisdiction gating needs each person's *physical* location — a fact you don't reliably
  have (remote/travel/VPN); the failure mode is the one that matters.
- **Cutting is a distribution advantage:** unpaired speech → unattributed gap is already the
  degradation-ladder default; a fallback that makes mixed rooms "work" removes the reason to
  pair. "We do not capture non-users" is a clean procurement answer.
- **Preserves the architectural advantage:** system-audio capture with attribution likely
  reintroduces biometric-identifier questions (Illinois BIPA — separate regime, private right of
  action). The paired-client pivot's whole point was attribution without voiceprint diarization;
  this one feature spends that.
- **Consent-scope fix regardless of the cut:** move `pairing_consents` from pairwise to
  **session scope** with explicit "your input may appear on cards visible to everyone in the
  session." Consent is a property of the session's participant set, not a user account →
  re-affirm on composition change (same TOCTOU class as T2). Capture consent ≠ storage consent
  (the Decision Record outlives the meeting) — a third, separate question.
- **Ask a lawyer** — the one issue where that's the real answer, not a hedge. A couple hours of a
  tech-privacy lawyer now vs finding out during a deal.
- **PRD edits:** cut/deprecate F4.7 + the §7.3 system-audio rung + §12.3 optional-capture line;
  §14 `pairing_consents` → session scope; §12.4 rewrite; elevate R6/R7.

### OV-13 — AD-1 clock-sync timing (cross-model tension) — RESOLVED: bake-off in Phase 3 planning
Decide server-arrival ordering vs clock-reconstruction *before* F5/§15 are built around clock
offsets (don't design around a maybe-deleted subsystem). Two design constraints:
- **Judge the bake-off on card quality from the merged transcript, not timestamp accuracy** — the
  consumer is an LLM that tolerates modest misordering far better than the error-margin machinery
  implies. Otherwise clock-reconstruction wins a metric nobody cares about.
- **Include a mixed-network session** (VPN/hotel wifi) in the Phase 0 recordings, or the bake-off
  flatters server-arrival.
- **PRD edits:** AD-1 (move to Phase 3 planning + judge on card quality + require a mixed-network
  recording), and hold F5/§15 detailed design until it resolves.

### Confirmed-concrete outside-voice findings (folded into the change-list)
- **OV-2** — In-person breaks device-attribution — RESOLVED (co-location detection + room mode in
  v1; headsets is the honest answer). It's not "degraded," it's *confidently incorrect* (N
  transcripts of one sentence, N mis-attributions, a false-premise card) — the system must
  **detect** it, not carry a disclaimer.
  - **Co-location detection, cheap, in v1:** cross-correlate a low-bandwidth (~20Hz) audio-energy
    envelope between clients; high correlation at sub-20ms lag = same room. ~a day, no DSP, no
    reliance on users saying they're in a room.
  - **Nominate, don't arbitrate:** elect one room-capture client (best avg SNR, or first to join),
    suspend the others' capture, mark that room's utterances unattributed (optional self-ID). One
    clean transcript, correct content, no duplicated STT, no false attribution.
  - **Say the real answer: headsets.** In-room earbuds restore close-talk mics and device
    attribution works. Honest position: "in-person fully supported with headsets; without them,
    room mode with no per-speaker attribution."
  - **Do it now, not Phase 3+:** undetected co-location = ~6x STT on the largest COGS line (pays
    for itself) and would trip §12.6/P1 degradation for a reason unrelated to contentiousness;
    also demos happen in rooms (room mode is demo insurance). Full per-utterance arbitration waits
    for Phase 3+ with its own test — use correlation to detect the room, not to pick a dominant
    speaker.
  - **PRD edits:** §6.1 (device-attribution caveat + headsets), F4/§16 (co-location detection +
    room mode), R7 (raise + point at detection), §12.2 (co-location STT-blowup note).
- **OV-3** — The *median* 7s (not just the tail) may miss the moment: 7s + wait-for-pause + read
  time. Measure card-arrival-vs-moment-relevance in Phase 0/4; if cards land post-moment the value
  is post-meeting. Sharpens the p95/p99 fold. **PRD edits:** §12.1, §20.
- **OV-5** — Solo mode may cannibalize the paired thesis; pre-register the invite-conversion rate
  that kills the paired bet and what the product is at 5%. **PRD edits:** §20, Open Q8.
- **OV-6** — Coverage is p^N (0.9^8 = 43% full coverage). G1 measures auto-pair among the
  installed, not room coverage → green while meetings run degraded. North-star metric should be
  "% of decision-bearing meetings with all disputants paired." **PRD edits:** G1, §20.
- **OV-7** — Break-even double-counts COGS: §12.2's <$2 is a *whole-session* hour (55 speech-min,
  8 syntheses total); §18.4 charges each user $2×6. Real per-user COGS ≈ $2/attendees. **Margins
  are likely far better than the stated 66%** — rebuild §18.4 per-session with an attendee
  distribution. **PRD edits:** §18.4, §18.2/§18.3.
- **OV-8** — `premise_challenged.basis` (F7.1, ~L375) reconstructs the "private" directed answer
  that L370 promises never reaches the Coordinator. Send only the scored boolean + confidence +
  thread_id across the private→Coordinator boundary. **PRD edits:** F7.1.
- **OV-10** — No erasure story for the "indefinite," embedded, supersede-linked Decision Index
  (personal data: dissent, owner, quotes). Design tombstoning + re-embedding before the index
  compounds. **PRD edits:** §12.3/§14 retention, F10.1.
- **OV-11** — Judgment layer (triage+agents+coordinator) is Anthropic-only; §12.8's provider
  interface is intra-Anthropic A/B. Make it genuinely cross-vendor with a defined fallback tier,
  same discipline as STT. **PRD edits:** §12.8, §13, R22.
- **OV-12** — Bhutan/remote pilot (Open Q11) collides with the latency/clock budget (R5 bias is
  worse on uplink-constrained links) AND makes the golden set out-of-distribution for the US
  beachhead. Recruit part of Phase 0 from the real beachhead profile; test on representative
  connections. **PRD edits:** Open Q11, §12.7 (population validity), Phase 0.
