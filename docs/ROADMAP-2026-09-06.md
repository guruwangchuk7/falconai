## Next: auto-supersession (the immediate build)

**Goal:** Falcon automatically detects when a new decision reverses an earlier one and *proposes* the
link; the human confirms with one tap. Keeps memory current without manual linking, and without the
risk of silently-wrong auto-links. This is what makes the decision timeline build itself from real
meetings instead of needing seeded data.

**Task skeleton (brainstorm → spec first):**
1. **Detector (core)** — `findSupersedeCandidate(newDecisionId)`: embedding nearest-neighbour over
   *confirmed* same-topic decisions → a conservative LLM "does this reverse that?" check →
   `{candidateId, confidence, reason}` or null.
2. **Trigger** — run just after a decision is **confirmed** (both records must be confirmed to link).
3. **Proposal storage** — persist the suggested link until acted on.
4. **Confirm surface (web)** — a banner: *"Looks like this replaces 'Use SQLite' — Link them? / Not a
   replacement."* One tap calls the existing `supersedeDecision`.
5. **Guardrails** — conservative threshold, never auto-apply, don't re-propose a dismissed pair,
   idempotent.
6. **Tests** — unit (stubbed LLM/embeddings) + integration (real reversal linked; unrelated not).

Backend (`supersedeDecision` + the `action:'supersede'` API route) already exists — this is detection +
a proposal surface.

Then: **US2** (per-person agents + publish-time ACL-intersection) → **US3** (open-thread tracking) →
**Phase 4 live mediation** — still gated on the WoZ mediation-validation before committing to build.

## Integrations (a parallel breadth track — NOT a US2/US3 gate)

| Built | Not built yet |
|---|---|
| GitHub (synced, proven) · Jira · Linear | Gmail · Slack · Google Docs · Calendar · Notion · Microsoft |

Each source is **one adapter** (OAuth + webhook-for-live + poll-for-history) behind the existing
source-agnostic pipeline (ingest → embed → retrieve → mine). Two roles: *context sources* (Gmail, Docs,
Calendar) pull info in for grounding; *capture sources* (meetings/mic, Slack) are where decisions and
commitments get made. Adding sources is incremental and independent of the US2/US3 track. Recommended
order: **Gmail → Slack → Docs/Calendar** (validate-before-build: grow a source when usage shows demand).
